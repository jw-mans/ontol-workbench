# Избавление онтологий от циклов: что решается за полином, а что нет

Заметка по исследовательскому вопросу: «онтология как конечный автомат,
запрещённые пути как регулярная грамматика, пересечение языков вместо DFS —
можем ли мы за полиномиальное время избавить онтологии от циклов, и
параллелится ли это?»

Короткий ответ: обнаружить и локализовать циклы (в том числе помеченные,
заданные грамматикой) — полином, и это отлично параллелится матрично.
Перечислять все циклы — экспоненциальный тупик, и это не нужно. Минимально
удалить циклы — NP-трудно в общем случае, но для онтологий есть два спасения:
конденсация (для одноимённых циклов) и малый параметр нарушений (FPT).

## 1. Три разные задачи, которые нельзя смешивать

| Задача | Сложность | Комментарий |
|---|---|---|
| Обнаружить цикл / путь под грамматикой | полином | линейно для регулярных шаблонов, ~кубик для КС |
| Перечислить все циклы | экспонента | простых циклов экспоненциально много; не наша цель |
| Удалить циклы минимальным вмешательством | NP-трудно | Feedback Arc/Vertex Set (Карп, 1972) |

Интуиция «найдём все циклы и удалим» упирается во вторую строку. Правильная
схема: полиномиальный оракул нарушений + точечный ремонт (разделы 5–6).

## 2. «Пересечение автоматов» — это RPQ, и оно уже опубликовано

Предложенная конструкция (онтология = НКА, где концепты — состояния, типы
стрелок — метки; запрет = регулярный язык; пересечение = наличие плохих путей)
известна как **Regular Path Queries (RPQ)**. Реализация — произведение
автоматов: вершины `(v, q)`, рёбра только при совпадении меток; «в онтологии
есть путь из запрещённого языка» = достижимость в произведении.

Две поправки к исходной формулировке:

* **НКА → ДКА не нужен.** Для непустоты пересечения детерминизация не
  требуется никогда: произведение строится прямо с НКА. Детерминизация стоит
  экспоненту в худшем случае — шаг просто выбрасывается.
* **Матричная форма этой идеи уже сделана той же группой, чью статью мы
  обсуждаем.** У Азимова и Григорьева, помимо матричного CFPQ, есть алгоритм
  через **произведение Кронекера**: грамматика представляется (рекурсивным)
  автоматом, пересечение с графом считается кронекеровым произведением булевых
  матриц смежности + транзитивным замыканием. Для чисто регулярного запрета
  рекурсия вырождается — остаётся буквально «граф × НКА + замыкание». Есть
  GPU/GraphBLAS-реализации (СПбГУ). Искать: *Kronecker product CFPQ*.

## 3. Иерархия шаблонов: где хватает линейного времени

| Класс запрета | Детекция | Чем |
|---|---|---|
| «просто цикл» | `O(V + E)` | Тарьян / SCC |
| регулярный (`a⁺b⁺a⁺b⁺` — регулярен!) | `O(V·|Q| + E·|Δ|)` — линейно | произведение + SCC/BFS |
| контекстно-свободный (`aⁿbⁿ`) | ~`O(n³)` | CFPQ (Азимов–Григорьев) |

Практический вывод для нашего кода: антипаттерн `a⁺b⁺a⁺b⁺` регулярен и
ловится линейно. Кубик оправдан, только если появятся действительно
КС-запреты (сбалансированные вложенности). Замер на реальных данных —
раздел 7. **Замена внедрена**: `cfpq_validator.validate_uml_cycles` переведён
на линейный RPQ-детектор (`uml_dsl/rpq_cycles.py`) при прежнем контракте;
исходный матричный CFPQ сохранён в `cfpq_matrix.py` для будущих КС-запретов,
бенчи в `tools/rpq_cycles/` сверяют боевой детектор с ним регрессионно.

Транзитивное замыкание общего вида (кубик) и алгоритмы `O(V·E)` для «какой-то
цикл есть» на фоне линейного SCC не нужны вовсе — они проигрывают уже на
постановке.

## 4. Тонкость: обходы, а не простые циклы

Диагональ `(i,i)` у CFPQ/произведения означает замкнутый **обход** (walk,
повторы вершин разрешены), удовлетворяющий грамматике — не простой цикл. Для
детекции это то, что нужно. Но задача ремонта ставится так: разорвать все
принимающие циклы **в произведении** `G × R`. Одно ребро онтологии присутствует
в произведении в нескольких копиях (по одной на каждый переход автомата с этой
меткой), удаляется — вся группа сразу. Это *group feedback arc set*: остаётся
NP-трудной, но постановка корректна (наивное «FAS на исходном графе» — нет).

## 5. Одноимённые циклы наследования: не удалять, а конденсировать

Цикл `A ⊑ B ⊑ … ⊑ A` логически означает эквивалентность участников:
`A ≡ B ≡ …`. Каноническая практика таксономий — **схлопнуть SCC в один
концепт** (конденсация):

* линейное время (Тарьян), параллелится через замыкание;
* семантически без потерь: циклические subclassOf ровно это и утверждают;
* вопрос «какое ребро минимально удалить» для одноимённых циклов снимается.

NP-трудное ядро остаётся только у **разнометочных** циклов (наследование +
зависимость, как abab), где эквивалентность не выводится.

## 6. Минимальный ремонт разнометочных циклов

* В общем случае — NP-трудно (FAS/FVS), апроксимации тоже трудные.
* **FPT по числу нарушений `k`**: направленный FVS решается за
  `O(f(k)·poly(n))` (Chen, Liu, Lu, O'Sullivan, Razgon, 2008). Если онтология
  «почти лес», `k` мал — фактически полином.
* **По древесной ширине**: `2^{O(tw·log tw)}·n` (Bonamy и др.), и под ETH
  лучше нельзя. Для ручных онтологий tw мал.
* Осторожно с посылкой «онтология — почти лес»: она верна для ручных онтологий
  и **неверна для автоизвлечённых**. Пример — выход DiGR по дискретной
  математике: 5 из 11 файлов содержат циклы/антипаттерны, «обобщение»
  порождается из со-встречаемости и образует плотные кластеры
  (`08_n7графы.tdl`: 109 классов, 164 связи). Малость `k` надо мерить, не
  постулировать.

Практичная точная схема — **ленивая генерация циклов (implicit hitting set)**,
как в современных точных FAS-решателях:

```
повторять:
  H ← минимальный hitting set накопленных циклов (маленький ILP)
  найти нарушающий цикл в G − H          ← полином: произведение+SCC или CFPQ
  если нет — H оптимален, стоп
  иначе добавить цикл в набор ограничений
```

Оракул нарушений — ровно наш детектор; циклов-ограничений на практике нужны
единицы, а не экспонента. Это и есть ответ на «поможет ли алгоритм как для
КС-грамматик найти все циклы»: он не перечислитель, он **оракул**, и в этой
роли его достаточно для точного ремонта.

## 7. Эксперимент: RPQ против CFPQ на данных DiGR

Прототип: `tools/rpq_cycles/` (`rpq_detect.py` — произведение с НКА + SCC,
чистый Python; `bench.py` — сравнение с матричным CFPQ на scipy). Оба детектора
получают один и тот же помеченный граф; равенство множеств нарушителей
проверяется на каждом файле. Результаты (11 онтологий DiGR, минимум из 7
прогонов; полная таблица — `tools/rpq_cycles/results.md`):

| | CFPQ (scipy) | RPQ (чистый Python) | Ускорение |
|---|---:|---:|---:|
| Все 11 файлов, оба шаблона | 297.6 мс | 10.7 мс | **×27.8** |
| Диапазон по файлам | 8.8–129.6 мс | 0.15–6.4 мс | ×20–×106 |

Множества нарушителей совпали на всех файлах (и циклы наследования, и abab).
Выигрыш даёт алгоритм (линейность), а не константы: интерпретируемый Python
обгоняет C-код scipy на порядок+.

## 8. Параллельность: почему уходить от DFS — правильно, но не из-за скорости

* Последовательно DFS не побить: детекция «просто цикла» и так линейна.
* Но **DFS как алгоритм внутренне последователен** (лексикографический DFS
  P-полон — Reif, 1985); параллелить его — тупик.
* Сама **задача** достижимости/цикла лежит в NC: степени булевой матрицы.
  Матричная постановка (Кронекер + замыкание) — это готовая параллельная
  форма, ложащаяся на GraphBLAS/GPU, и она же выражает помеченные запреты,
  которые DFS не выражает вовсе.

Итог по «будет ли быстрее DFS»: последовательно — нет; выигрыш в
выразительности (регулярные/КС-запреты) и в масштабируемости (булева
линейная алгебра).

### Параллельная реализация: замер

Прототип `tools/rpq_cycles/kron_parallel.py` — идея «пересечение автоматов»
в матричной форме: `M = Σ_l A_l ⊗ N_l` (произведение Кронекера графа с НКА),
транзитивное замыкание повторным булевым квадратом; квадрат — плотный
float32-matmul BLAS, многопоточность даёт сам BLAS (тот же код, меняется
только число потоков). Замер на 12 ядрах (OpenBLAS, сабпроцессы с разным
лимитом потоков; полная таблица — `tools/rpq_cycles/results_parallel.md`):

| Вершин | 1 поток | 12 потоков | Ускорение | Чистый Python BFS |
|---:|---:|---:|---:|---:|
| 400 | 1.03 с | 0.37 с | ×2.8 | 0.007 с |
| 800 | 7.77 с | 2.46 с | ×3.2 | 0.019 с |
| 1200 | 25.0 с | 6.2 с | ×4.0 | 0.037 с |

Корректность сверена: матричный детектор == эталонный BFS на всех 11
онтологиях DiGR по обоим шаблонам.

Честные выводы из таблицы:

* **параллелится** — тот же код ускоряется числом ядер без изменений, что и
  требовалось; BFS/DFS так ускорить нельзя в принципе;
* **но на разреженных онтологиях реального размера последовательный BFS
  быстрее на 2–3 порядка**: детекция линейна, а плотное замыкание платит
  `O((nQ)³·log d)` за в основном нулевую матрицу. Плотный BLAS — демонстрация
  масштабируемости, не продакшен;
* ниша матричной формы: (1) действительно большие/плотные графы и GPU,
  (2) батчи запросов, (3) когда нужно ВСЁ отношение достижимости (для
  ремонта/свидетелей), а не только диагональ. Продакшен-путь — разреженный
  GraphBLAS (SuiteSparse) или CUDA, как в реализациях группы Григорьева:
  та же алгебра, но без платы за нули.

### Разреженный GraphBLAS: параллельно И быстрее последовательного BFS

Реализация `tools/rpq_cycles/graphblas_impl.py` — та же алгебра (настоящий
`GrB_kronecker` + замыкание квадратом через `mxm` с семирингом LOR_LAND) на
SuiteSparse:GraphBLAS 9.4.5 (CPU/OpenMP, `pip install python-graphblas` —
CUDA не требуется). Потоки переключаются на лету. Замер на 12 ядрах
(`tools/rpq_cycles/results_graphblas.md`):

| Вершин | 1 поток | 12 потоков | От ядер | Python BFS | GraphBLAS vs BFS |
|---:|---:|---:|---:|---:|---:|
| 1200 | 0.026 с | 0.023 с | ×1.2 | 0.037 с | ×1.6 |
| 5000 | 0.152 с | 0.071 с | ×2.1 | 0.450 с | ×6.3 |
| 20000 | 1.10 с | 0.335 с | ×3.3 | 6.19 с | ×18.5 |

Корректность сверена с эталоном на всех 11 онтологиях DiGR. Для сравнения:
плотная BLAS-версия на n=1200 тратила 6.2 с — разреженность даёт ×250 на том
же размере, потому что перестаёт платить за нули.

Это закрывает вопрос целиком: **разреженная матричная форма одновременно
параллелится (×3.3 от 12 ядер на n=20000, растёт с размером) и уже с
n≈1200 обгоняет последовательный BFS** — потому что BFS считает диагональ
per-source (квадратично), а замыкание получает всё отношение достижимости
разом. На онтологиях в сотни вершин по-прежнему достаточно BFS; матричный
путь — для больших графов, батчей и этапа ремонта.

## 9. Сводка ответов

1. Идея «онтология × автомат запретов» верна; в матричной форме уже
   опубликована (Kronecker CFPQ, Азимов–Григорьев). Детерминизацию выбросить.
2. Регулярные запреты (включая abab) — линейная детекция; кубик CFPQ — только
   для настоящих КС-запретов. На наших данных линейный детектор в ~28 раз
   быстрее при совпадающих ответах.
3. «Все циклы» не нужны: детектор — оракул нарушений, точный минимальный
   ремонт — ленивой генерацией, каждая итерация полиномиальна.
4. Одноимённые циклы наследования чинятся конденсацией SCC — полином, без
   потерь. NP-трудность живёт только в разнометочных циклах; там FPT по `k`
   и ограниченная древесная ширина.
5. «Онтология — почти лес» — проверять на данных: для автоизвлечённых
   (DiGR) уже неверно.
