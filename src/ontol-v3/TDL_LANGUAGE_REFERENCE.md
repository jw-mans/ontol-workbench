# Справочник языка TDL

TDL, Text Diagram Language, — текстовый язык Ontol v3 для описания UML-диаграмм
классов. Один `.tdl`-файл описывает набор классификаторов, связей между ними и,
при необходимости, ручное размещение элементов на диаграмме.

Документ устроен как справочник: каждая конструкция описана через назначение,
синтаксис, пример и ожидаемый вид на SVG-диаграмме.

## Минимальный пример

```tdl
КЛАСС User
АТРИБУТЫ
  + id : Integer
  + name : String
КОНЕЦ КЛАСС
```

На диаграмме появится один UML-класс `User` с двумя публичными атрибутами.

SVG-пример: [example.svg](examples/tdl/basic/example.svg)

## Обозначения

В синтаксических шаблонах используются такие обозначения:

| Обозначение | Значение |
|---|---|
| `<Имя>` | имя класса, интерфейса, типа, параметра или связи |
| `<Тип>` | имя типа: примитив, класс, интерфейс, тип данных или параметр шаблона |
| `<кратность>` | кратность: `[1]`, `[0..1]`, `[0..*]`, `[*]` |
| `<роль>` | имя конца ассоциации |
| `<строка>` | строковый литерал в двойных кавычках |
| `[...]` | необязательная часть синтаксиса |

Ключевые слова в примерах написаны верхним регистром, но язык распознает их как
ключевые слова независимо от регистра. Имена элементов сохраняют написание.

## Общие правила

### Комментарии

Строка, начинающаяся с `--`, считается комментарием.

```tdl
-- Это комментарий
КЛАСС User
КОНЕЦ КЛАСС
```

### Строки

Строковые значения пишутся в двойных кавычках.

```tdl
АССОЦИАЦИЯ User [1] : owner -- Account [0..*] : accounts ИМЯ "owns"
```

### Видимость

Перед атрибутами и операциями можно указывать UML-видимость.

| Символ | Значение |
|---|---|
| `+` | public |
| `-` | private |
| `#` | protected |
| `~` | package |

```tdl
+ publicName : String
- secret : String
# inheritedCode : Integer
~ packageFlag : Boolean
```

### Кратность

Кратность указывается в квадратных скобках после имени атрибута или участника
ассоциации.

```tdl
+ items [0..*] : Item
АССОЦИАЦИЯ Order [1] : order -- LineItem [0..*] : items
```

Поддерживаемые формы записи:

```tdl
[1]
[0..1]
[0..*]
[*]
```

### Атрибут

Синтаксис:

```tdl
[видимость] <имя> [<кратность>] [: <Тип>] [= <значение>] [{ только_чтение }]
```

Пример:

```tdl
АТРИБУТЫ
  + name : String
  - code : Integer = 7 { только_чтение }
  + items [0..*] : Item
```

На диаграмме атрибуты отображаются в секции атрибутов класса. Кратность
показывается рядом с именем атрибута.

### Операция

Синтаксис:

```tdl
[видимость] <имя>([параметры]) [: <ТипВозврата>] [{ свойства }]
```

Параметры операции:

```tdl
<имя> [: <Тип>] [= <значение>]
```

Пример:

```tdl
ОПЕРАЦИИ
  + add(item : Item, count : Integer = 1) : Boolean
  + find(id : String) : Item { запрос }
```

Свойства операции записываются в фигурных скобках через запятую:

```tdl
{ абстрактная }
{ запрос }
{ лист }
{ запрос, лист }
```

## КЛАСС

Назначение: описывает обычный UML-класс.

Синтаксис:

```tdl
КЛАСС <Имя>
[АТРИБУТЫ
  <атрибуты>]
[ОПЕРАЦИИ
  <операции>]
КОНЕЦ КЛАСС
```

Пример:

```tdl
КЛАСС User
АТРИБУТЫ
  + id : Integer
  + name : String
ОПЕРАЦИИ
  + rename(newName : String)
КОНЕЦ КЛАСС
```

На SVG это прямоугольник класса с именем, секцией атрибутов и секцией операций.

## Абстрактный класс

Назначение: описывает UML-класс, который не предполагает прямого создания
экземпляров.

Синтаксис:

```tdl
КЛАСС <Имя> АБСТРАКТНЫЙ
[АТРИБУТЫ
  <атрибуты>]
[ОПЕРАЦИИ
  <операции>]
КОНЕЦ КЛАСС
```

Пример:

```tdl
КЛАСС Shape АБСТРАКТНЫЙ
ОПЕРАЦИИ
  + area() : Float { абстрактная }
КОНЕЦ КЛАСС
```

На SVG имя абстрактного класса отображается курсивом.

## ПЕРЕЧИСЛЕНИЕ

Назначение: описывает UML Enumeration.

Синтаксис:

```tdl
ПЕРЕЧИСЛЕНИЕ <Имя>
  <литерал>
  <литерал>
КОНЕЦ ПЕРЕЧИСЛЕНИЕ
```

Пример:

```tdl
ПЕРЕЧИСЛЕНИЕ OrderStatus
  NEW
  PAID
  CANCELLED
КОНЕЦ ПЕРЕЧИСЛЕНИЕ
```

На SVG перечисление отображается как классификатор со стереотипом enumeration и
литералами в секции атрибутов.

## ИНТЕРФЕЙС

Назначение: описывает UML Interface.

Синтаксис:

```tdl
ИНТЕРФЕЙС <Имя>
[АТРИБУТЫ
  <атрибуты>]
[ОПЕРАЦИИ
  <операции>]
КОНЕЦ ИНТЕРФЕЙС
```

Пример:

```tdl
ИНТЕРФЕЙС Repository
ОПЕРАЦИИ
  + save(entity : Entity)
  + find(id : String) : Entity
КОНЕЦ ИНТЕРФЕЙС
```

На SVG интерфейс отображается как классификатор со стереотипом interface и
визуальной меткой `I`. Операции интерфейса считаются абстрактными.

SVG-пример: [interfaces.svg](examples/tdl/basic/interfaces.svg)

## ТИП_ДАННЫХ

Назначение: описывает UML DataType, то есть значение без собственной объектной
идентичности.

Синтаксис:

```tdl
ТИП_ДАННЫХ <Имя>
[АТРИБУТЫ
  <атрибуты>]
[ОПЕРАЦИИ
  <операции>]
КОНЕЦ ТИП_ДАННЫХ
```

Пример:

```tdl
ТИП_ДАННЫХ Money
АТРИБУТЫ
  + amount : Decimal
  + currency : String
ОПЕРАЦИИ
  + add(other : Money) : Money
КОНЕЦ ТИП_ДАННЫХ
```

На SVG тип данных отображается как классификатор со стереотипом dataType и
визуальной меткой `D`.

SVG-пример: [data_types.svg](examples/tdl/basic/data_types.svg)

## ШАБЛОН

Назначение: описывает параметризованный UML-классификатор.

Синтаксис:

```tdl
ШАБЛОН <Имя>
[ПАРАМЕТРЫ
  <Параметр>
  <Параметр> [: <Тип>] [= <ЗначениеПоУмолчанию>]]
[АТРИБУТЫ
  <атрибуты>]
[ОПЕРАЦИИ
  <операции>]
КОНЕЦ ШАБЛОН
```

Пример:

```tdl
ШАБЛОН Repository
ПАРАМЕТРЫ
  T
АТРИБУТЫ
  + items [0..*] : T
ОПЕРАЦИИ
  + find(id : String) : T
  + save(entity : T)
КОНЕЦ ШАБЛОН
```

На SVG шаблон отображается как классификатор с областью параметров шаблона.

SVG-пример: [templates.svg](examples/tdl/basic/templates.svg)

## ПОДСТАНОВКА

Назначение: описывает использование шаблона с конкретными фактическими
параметрами.

Синтаксис:

```tdl
ПОДСТАНОВКА <СвязанныйЭлемент> -> <Шаблон> { <ФормальныйПараметр> = <ФактическийТип> }
```

Для нескольких параметров используется запятая:

```tdl
ПОДСТАНОВКА PairOfUsers -> Pair { Left = User, Right = User }
```

Пример:

```tdl
ШАБЛОН Box
ПАРАМЕТРЫ
  T
АТРИБУТЫ
  + value : T
КОНЕЦ ШАБЛОН

КЛАСС User
АТРИБУТЫ
  + name : String
КОНЕЦ КЛАСС

КЛАСС UserBox
АТРИБУТЫ
  + value : User
КОНЕЦ КЛАСС

ПОДСТАНОВКА UserBox -> Box { T = User }
```

На SVG подстановка отображается как зависимость от конкретного элемента к
шаблону с подписью bind и метаданными фактических параметров.

## КЛАСС_АССОЦИАЦИИ

Назначение: описывает UML Association Class — ассоциацию, у которой есть
собственные атрибуты и операции.

Синтаксис:

```tdl
КЛАСС_АССОЦИАЦИИ <ИмяКлассаАссоциации>
АССОЦИАЦИЯ <Участник1> [<кратность>] [: <роль>] -- <Участник2> [<кратность>] [: <роль>] [ИМЯ "<имя связи>"]
[АТРИБУТЫ
  <атрибуты>]
[ОПЕРАЦИИ
  <операции>]
КОНЕЦ КЛАСС_АССОЦИАЦИИ
```

Пример:

```tdl
КЛАСС Student
АТРИБУТЫ
  + name : String
КОНЕЦ КЛАСС

КЛАСС Course
АТРИБУТЫ
  + title : String
КОНЕЦ КЛАСС

КЛАСС_АССОЦИАЦИИ Enrollment
АССОЦИАЦИЯ Student [0..*] : student -- Course [0..*] : course ИМЯ "enrolls"
АТРИБУТЫ
  + enrolledAt : Date
  + grade : String
ОПЕРАЦИИ
  + confirm() : Boolean
КОНЕЦ КЛАСС_АССОЦИАЦИИ
```

На SVG основная ассоциация рисуется как единая линия между участниками, а класс
ассоциации соединяется с этой линией пунктиром через точку привязки.

SVG-примеры:

- [association_classes.svg](examples/tdl/basic/association_classes.svg)
- [association_classes_rich.svg](examples/tdl/basic/association_classes_rich.svg)

## АССОЦИАЦИЯ

Назначение: описывает бинарную UML Association между двумя классификаторами.

Синтаксис:

```tdl
АССОЦИАЦИЯ <Участник1> [<кратность>] [: <роль>] -- <Участник2> [<кратность>] [: <роль>] [ИМЯ "<имя>"] [ПРОИЗВОДНАЯ]
```

Пример:

```tdl
КЛАСС Customer
КОНЕЦ КЛАСС

КЛАСС Order
КОНЕЦ КЛАСС

АССОЦИАЦИЯ Customer [1] : customer -- Order [0..*] : orders ИМЯ "places"
```

На SVG ассоциация отображается сплошной линией. Кратности и роли подписываются
у концов связи, имя связи — рядом с линией.

## АГРЕГАЦИЯ

Назначение: описывает UML Aggregation, то есть слабую связь whole-part.

Синтаксис:

```tdl
АГРЕГАЦИЯ <Целое> [<кратность>] [: <роль>] -- <Часть> [<кратность>] [: <роль>] [ИМЯ "<имя>"]
```

Пример:

```tdl
КЛАСС Department
КОНЕЦ КЛАСС

КЛАСС Course
КОНЕЦ КЛАСС

АГРЕГАЦИЯ Department [1] : department -- Course [0..*] : courses ИМЯ "offers"
```

На SVG агрегация отображается сплошной линией с пустым ромбом на стороне
целого.

## КОМПОЗИЦИЯ

Назначение: описывает UML Composition, то есть сильную связь whole-part.

Синтаксис:

```tdl
КОМПОЗИЦИЯ <Целое> [<кратность>] [: <роль>] -- <Часть> [<кратность>] [: <роль>] [ИМЯ "<имя>"]
```

Пример:

```tdl
КЛАСС Order
КОНЕЦ КЛАСС

КЛАСС LineItem
КОНЕЦ КЛАСС

КОМПОЗИЦИЯ Order [1] : order -- LineItem [1..*] : items ИМЯ "contains"
```

На SVG композиция отображается сплошной линией с закрашенным ромбом на стороне
целого.

## ОБОБЩЕНИЕ

Назначение: описывает UML Generalization, то есть наследование.

Синтаксис:

```tdl
ОБОБЩЕНИЕ <Подкласс> -> <Суперкласс>
```

Пример:

```tdl
КЛАСС Animal
КОНЕЦ КЛАСС

КЛАСС Cat
КОНЕЦ КЛАСС

ОБОБЩЕНИЕ Cat -> Animal
```

На SVG обобщение отображается линией с пустым треугольником в сторону
суперкласса.

## РЕАЛИЗАЦИЯ

Назначение: описывает UML Realization — реализацию интерфейса классом.

Синтаксис:

```tdl
РЕАЛИЗАЦИЯ <Класс> -> <Интерфейс>
```

Пример:

```tdl
ИНТЕРФЕЙС Readable
ОПЕРАЦИИ
  + read() : String
КОНЕЦ ИНТЕРФЕЙС

КЛАСС FileReader
КОНЕЦ КЛАСС

РЕАЛИЗАЦИЯ FileReader -> Readable
```

На SVG реализация отображается пунктирной линией с пустым треугольником в
сторону интерфейса.

SVG-пример: [interfaces.svg](examples/tdl/basic/interfaces.svg)

## ЗАВИСИМОСТЬ

Назначение: описывает UML Dependency между двумя классификаторами.

Синтаксис:

```tdl
ЗАВИСИМОСТЬ <Клиент> -> <Поставщик> [стереотип]
```

Стереотип можно писать идентификатором или строкой.

Пример:

```tdl
КЛАСС ReportService
КОНЕЦ КЛАСС

КЛАСС PdfExporter
КОНЕЦ КЛАСС

ЗАВИСИМОСТЬ ReportService -> PdfExporter use
```

На SVG зависимость отображается пунктирной стрелкой от клиента к поставщику.

## РАЗМЕЩЕНИЕ (устарело)

Назначение: задает ручные координаты элементов диаграммы в старых `.tdl`
примерах. Для актуального рендера Ontol v3 основным способом считается
автоматическая раскладка через Graphviz и отдельный анализ планарности.

Блок `РАЗМЕЩЕНИЕ` сохранен для совместимости со старыми примерами. Из команд
ручного размещения практически используется только `ЗАФИКСИРОВАТЬ`: она
сохраняет координаты элемента в модели. Остальные команды ручного размещения
могут распознаваться парсером, но не являются основной поддерживаемой частью
языка.

Синтаксис блока:

```tdl
РАЗМЕЩЕНИЕ
  ЗАФИКСИРОВАТЬ <Элемент> В ( <x> , <y> )
КОНЕЦ РАЗМЕЩЕНИЕ
```

Пример:

```tdl
КЛАСС A
КОНЕЦ КЛАСС

КЛАСС B
КОНЕЦ КЛАСС

АССОЦИАЦИЯ A -- B

РАЗМЕЩЕНИЕ
  ЗАФИКСИРОВАТЬ A В ( 80 , 80 )
  ЗАФИКСИРОВАТЬ B В ( 420 , 80 )
КОНЕЦ РАЗМЕЩЕНИЕ
```

В старом сценарии элементы размещались в указанных координатах. Координата
задает левый верхний угол блока. В новом обычном рендере эту функцию в целом
не стоит использовать; она оставлена главным образом для старых `.tdl`-примеров.
