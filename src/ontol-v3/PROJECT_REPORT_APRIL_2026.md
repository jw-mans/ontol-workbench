# Проектный отчет Ontol v3, апрель 2026

Этот документ сохраняет отчетную часть проекта для апрельской версии Ontol v3.
Он не является основной инструкцией по запуску. Актуальные команды, зависимости
и структура проекта описаны в [README.md](README.md).

## Обзор проекта

Ontol v3 - система для работы с UML-диаграммами классов через текстовый формат
TDL, Text Diagram Language. Проект объединяет:

- синтаксис TDL для описания UML-диаграмм классов;
- доменную модель на Pydantic;
- семантическую валидацию;
- SVG-рендер;
- обратный парсинг из SVG в модель;
- демонстрационный интерфейс на Streamlit.

Дата разработки: апрель 2026.

Основные технологии:

- Python 3.10+;
- Pydantic v2;
- Graphviz;
- Streamlit.

## Цели

Проект был создан как полный цикл работы с UML-диаграммами классов:

1. описать диаграмму в текстовом языке;
2. построить типизированную модель из этого описания;
3. проверить семантику диаграммы;
4. сгенерировать стабильное SVG-представление;
5. разобрать сгенерированный SVG обратно в структурированные данные.

Исходная проблема заключалась в том, что ручное позиционирование SVG и ручное
описание стрелок трудно поддерживать, проверять и надежно парсить обратно.

## Архитектура

Исторический пайплайн проекта:

```text
Текст TDL
-> лексер
-> парсер
-> AST
-> Pydantic-модель
-> семантическая валидация
-> генерация SVG
-> SVG-парсер
-> Pydantic-модель
```

Текущий рендер использует Graphviz для расчета раскладки, а собственный код
пакета отвечает за UML-структуру SVG, маркеры, подписи, кратности,
data-атрибуты и темы.

## Основные модули

`uml_dsl/models.py`

Определяет UML-классификаторы, атрибуты, операции, параметры, кратности и SVG
фрагменты для блоков классов.

`uml_dsl/relationships.py`

Определяет UML-отношения: ассоциации, концы ассоциаций, зависимости, обобщения
и реализации.

`uml_dsl/diagram.py`

Содержит `ClassDiagram`, общую логику валидации, позиции элементов и публичный
вход `to_svg()`.

`uml_dsl/tdl_lexer.py`

Разбивает TDL-текст на ключевые слова, идентификаторы, литералы, операторы,
скобки, маркеры видимости и кратности.

`uml_dsl/tdl_parser.py`

Парсит токены в AST-документ.

`uml_dsl/tdl_ast.py`

Описывает AST dataclass-структуры, которые используются между парсером и
сборщиком модели.

`uml_dsl/tdl_build.py`

Строит Pydantic UML-модель из AST.

`uml_dsl/tdl_run.py`

Предоставляет CLI и вспомогательные Python-функции для рендера TDL в SVG.

`uml_dsl/graphviz_render.py`

Рендерит объекты `ClassDiagram` в SVG. Рендер строит DOT-граф, использует
Graphviz для расчета позиций и путей ребер, затем собирает итоговый SVG с
UML-маркерами, подписями, кратностями и data-атрибутами.

`uml_dsl/svg_parser.py`

Парсит SVG-результат обратно в Pydantic UML-модель.

`uml_dsl/export.py`

Предоставляет опциональный экспорт в PNG/JPG через CairoSVG и Pillow.

`uml_dsl/app.py`

Демонстрационное приложение Streamlit с вкладками рендера TDL и проверки SVG.

## Исторические этапы реализации

Этот раздел перенесен из старого README, чтобы README был рабочей документацией,
а отчетная часть оставалась отдельно.

### Шаг 1: data-атрибуты для классов

SVG-вывод классов был дополнен метаданными для обратного парсинга:

- `data-name`;
- `data-type="class"`;
- `data-stereotype`;
- `data-abstract`;
- счетчики атрибутов и операций.

### Шаг 2: data-атрибуты для отношений

SVG-вывод отношений был дополнен data-атрибутами для:

- ассоциаций;
- зависимостей;
- обобщений;
- реализаций;
- n-арных ассоциаций.

Это позволило восстанавливать семантическую информацию об отношениях из
сгенерированного SVG, а не опираться только на визуальную геометрию.

### Шаг 3: SVG -> Pydantic парсер

Был добавлен `svg_parser.py`, который парсит SVG обратно в объекты модели.
Парсер:

- читает XML;
- извлекает элементы диаграммы через data-атрибуты;
- восстанавливает классификаторы и отношения;
- восстанавливает позиции классов;
- возвращает диагностику через `ParseResult`.

### Шаг 4: тестовый скрипт парсера

Были добавлены генерация фикстур и проверка SVG-парсера. В текущей структуре
проекта эти исторические утилиты находятся здесь:

```text
tests/scripts/
tests/fixtures/svg_parser/
```

Позже рядом с ними был добавлен обычный pytest-набор для основного кода Ontol
v3. Он запускается отдельно от backend и frontend через `run_tests.py`.

### Шаг 5: Streamlit-приложение

Было добавлено Streamlit-приложение со следующими возможностями:

- загрузка SVG;
- предпросмотр SVG;
- проверка и парсинг;
- статистика по модели;
- JSON/details-вывод;
- рендер TDL в SVG;
- примеры для быстрого ручного тестирования.

## Область валидации

Проект проверяет:

- циклы наследования;
- конфликты множественного наследования;
- ссылки на неизвестные классификаторы;
- ссылки на типы атрибутов и параметров операций;
- концы отношений;
- ограничения композиции;
- разбор кратностей.

## Область рендера

Текущий рендер поддерживает:

- блоки классов и enum;
- атрибуты и операции;
- ассоциации с ролями и кратностями;
- маркеры агрегации и композиции;
- зависимости;
- обобщения;
- реализации;
- SVG-темы;
- маршрутизацию ребер через Graphviz;
- SVG data-атрибуты для обратного парсинга.

- семантическая валидация;
- SVG-генерация;
- обратный SVG-парсер;
