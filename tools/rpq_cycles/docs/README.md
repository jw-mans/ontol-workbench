# RPQ-детекция циклов: прототип к research-note

Прототип к [docs/research/cycle-free-ontologies.md](../../docs/research/cycle-free-ontologies.md):
оба шаблона циклов, которые сейчас ищет кубический матричный CFPQ
(`cfpq_validator`), регулярны — значит детектятся линейно через произведение
графа с конечным автоматом.

* `rpq_detect.py` — **ре-экспорт боевого детектора** из
  `src/ontol-v3/uml_dsl/rpq_cycles.py`: циклы наследования (SCC на
  'a'-рёбрах, Косарайю) и антипаттерн `a⁺b⁺a⁺b⁺` (произведение с
  5-состоянийным НКА + BFS). Реализация переехала из этого прототипа в
  движок — её использует `cfpq_validator.validate_uml_cycles` на каждой
  сборке TDL; бенчи ниже сверяют именно боевой код с оригинальным CFPQ.
* `bench.py` — сравнение с матричным CFPQ на 11 онтологиях DiGR: оба
  детектора получают один и тот же помеченный граф, множества нарушителей
  проверяются на равенство, время — минимум из 7 прогонов.
* `results.md` — результаты замера.
* `kron_parallel.py` — **параллельная матричная реализация**: произведение
  Кронекера `M = Σ_l A_l ⊗ N_l` + транзитивное замыкание повторным булевым
  квадратом (плотный float32-matmul BLAS; потоками управляет
  OPENBLAS/OMP_NUM_THREADS). Плюс генератор синтетики «лес + поперечные дуги»
  с посаженными abab-циклами.
* `bench_parallel.py` — корректность матричного детектора против эталона на
  DiGR-файлах + масштабирование по потокам (замеры в сабпроцессах — env BLAS
  надо задать до старта интерпретатора).
* `results_parallel.md` — результаты параллельного замера.
* `graphblas_impl.py` — **продакшен-вариант той же алгебры на
  SuiteSparse:GraphBLAS** (CPU/OpenMP, без CUDA): настоящий `GrB_kronecker`,
  замыкание через `mxm` с семирингом LOR_LAND, разреженные матрицы — не
  платим за нули. Требует `pip install python-graphblas`.
* `bench_graphblas.py` / `results_graphblas.md` — корректность на DiGR +
  масштабирование (потоки переключаются на лету через
  `gb.ss.config['nthreads']`).

```bash
python tools/rpq_cycles/bench.py
python tools/rpq_cycles/bench_parallel.py
python tools/rpq_cycles/bench_graphblas.py   # нужен python-graphblas
```

Итоги замеров:

* RPQ (чистый Python) против CFPQ (scipy): ответы совпали на всех 11 файлах,
  быстрее в ×20–×106 (суммарно ×27.8) — выигрывает алгоритм, не константы.
* Плотная BLAS-форма: тот же код ускоряется ядрами (×2.8–×4.0 на 12 ядрах,
  n=400–1200), корректность == эталон; но на разреженных онтологиях
  последовательный BFS быстрее на 2–3 порядка — плата за нули.
* **GraphBLAS (разреженно): параллельно И быстрее BFS** — корректность ==
  эталон на всех DiGR-файлах; n=20000: 0.335 с на 12 потоках (×3.3 от ядер),
  против 6.19 с у чистого BFS (×18.5); плотную версию на n=1200 обгоняет
  в ×250. Кроссовер с BFS — уже около n≈1200.
