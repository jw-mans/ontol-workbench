# Мост DiGR → ontol-v3 / v2-service

DiGR — экстрактор знаний: парсит текст лекций в AST, гоняет DSL-запросы
(найти сущность, где два понятия рядом, расстояние между ними), по шаблонам
определяет тип связи и выдаёт `.tdl` для онтола (и чанки в Qdrant для RAG). Сам
он ничего не рисует и онтологии не хранит.

`.tdl` от DiGR (`src/digr/ontology-pipeline/data/tdl/`) написан тем же диалектом
TDL, что рендерит ontol-v3, поэтому стыковка почти бесплатная. Здесь два моста.

## 1. Офлайн-батч: рендер папки в SVG + отчёт

```bash
python tools/digr_bridge/render_tdl_dir.py
# своя папка/выход:
python tools/digr_bridge/render_tdl_dir.py --in <папка .tdl> --out <папка>
```

На каждый файл — две фазы: сначала валидация (lex → parse → build →
`validate_all`, без graphviz), потом рендер (`dot` → SVG). Это отделяет «модель
кривая» от «на машине нет graphviz». Результат в `out/`:

- `<файл>.svg` — для всего, что удалось отрендерить;
- `report.md` / `report.json` — таблица со статусом каждого файла и причиной.

Статусы: `OK`, `OK (непланарный)`, `МОДЕЛЬ` (семантика не прошла), `СИНТАКСИС`,
`нет graphviz` (модель валидна, не установлен `dot`). Код возврата `1`, если
есть по-настоящему невалидные модели.

Флаг `--lenient` — мягкий режим (как в v2-service): семантические нарушения не
отклоняют файл, а уходят в предупреждения, диаграмма рисуется «как есть».
Синтаксис остаётся жёсткой ошибкой.

```bash
python tools/digr_bridge/render_tdl_dir.py --lenient
```

## 2. Импорт в v2-service (штатный REST)

Сервис уже умеет рендерить `.tdl` (диспетчер по расширению). Импортёр доводит
файлы до сервиса штатным путём — регистрация/логин → проект → файлы →
опционально сборка:

```bash
python tools/digr_bridge/push_to_service.py \
    --base http://localhost:8000 --email you@example.com --password secret \
    --project "DiGR дискретка" --build
```

Только stdlib (`urllib`), cookie-авторизация fastapi-users. Требует поднятого
стека v2-service.

## Что показал прогон (11 файлов дискретки)

Лексер/парсер приняли **все 11** — диалекты TDL совпадают. Но валидацию
ontol-v3 прошли не все:

| Итог | Файлов | Причина |
|---|---:|---|
| Валидны (рендерятся) | 6 | `01`, `03`, `04`, `06`, `08`, `11` |
| Отклонены | 5 | цикл наследования (`02`); antipattern `a⁺b⁺a⁺b⁺` (`05`, `09`, `10`); лимит композиций (`07`) |

Вывод: соединять «в лоб» нельзя — авто-извлечённые онтологии содержат циклы и
антипаттерны, которые валидатор ontol-v3 (в т.ч. CFPQ-проверка) режет жёстким
`ValueError`. Дальше на выбор: либо DiGR чистит онтологию перед выдачей TDL,
либо в рендер-пути ввести «мягкий» режим (рисовать с предупреждением вместо
отказа) — учитывая, что данные автоизвлечённые из текста.
